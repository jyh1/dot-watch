# Security and privacy

Dot signs in through ChatGPT's official website in an iPhone WKWebView. It reads the signed-in session for calls to `https://chatgpt.com` and transfers session material to the paired Watch through WatchConnectivity. No developer-run credential relay exists.

- Account tokens and filtered secure ChatGPT cookies use device-only Keychain storage, available after the device's first unlock following reboot.
- Session renewal requires the returned account identity to match the connected account.
- Ephemeral session-renewal, call and Dot-profile requests reject redirects. Apple's [background URLSession automatically follows redirects](https://developer.apple.com/documentation/foundation/downloading-files-in-the-background), bypassing the redirect delegate for transcription and message uploads. Their final responses must use HTTPS on `chatgpt.com` and match the original request path/query before the app accepts a transcript or receipt. This response check cannot prevent redirects or data transfer; an unexpected message response leaves delivery unconfirmed for manual review.
- SDP must include the remote certificate fingerprint before encrypted media is accepted.
- The widget stores no account data and starts the containing app through a validated call URL.
- Voice-message jobs persist the original account and Dot identifiers, message ID, timestamps, delivery state and any unsent transcript; tokens and cookies are not stored in the outbox.
- Recording has no fixed time cap. The recorder checks its real audio file size once per second and stops near the app's 10 MB recording size limit with room for finalization; enqueue and multipart construction both reject empty or oversized media and invalid durations.
- iPhone and Watch recordings and upload bodies use local file protection available after first unlock; the persistent outbox is excluded from backups. An unfinished draft is temporary: Cancel deletes it, and abandoned drafts are cleaned at the next process launch.
- Unsent or uncertain-delivery audio and transcripts remain on the recording device for manual retry/removal; there is no automatic expiration. After a confirmed message receipt is saved, media/upload bodies and the local transcript are removed. A temporary in-memory transcript preview can remain visible until reopening, completing a call, or queueing another recording; delivered text is not written back to disk. The receipt/status remains until removed, or until a later enqueue prunes sent records older than one day.
- Disconnect clears saved credentials and cancels mismatched uploads locally, and on Watch when the clearing update reaches it. It preserves the outbox, whose jobs can only retry with the original account and Dot; remove these jobs separately to erase their local content. A cancellation cannot recall a message already accepted by the server.
- The call trace records timing, state and short error diagnostics. Review logs before sharing; they are not a public support attachment by default.
- Call audio diagnostics are off by default and armed for one call only, without persisting the toggle across process restarts. They save decrypted incoming Opus audio, relative packet arrival/processing times and render timing locally; microphone audio, credentials, SDP and network addresses are not captured. The agent can speak private conversation content, so these files are sensitive audio recordings. Each capture is limited to five minutes or 10 MiB and uses bounded asynchronous writes; reaching a limit does not end the call. The diagnostic folder is excluded from backups and uses file protection after first unlock on iPhone/Watch. At most five recordings / 64 MiB are retained, with older completed files pruned. Export on iPhone and transfer from Watch happen only through explicit user actions. Deleting an app copy does not remove previously exported copies. Offline replay WAV files also contain conversation audio; keep them private.
- The iPhone login web view uses persistent website storage. The in-app Disconnect action clears the app's saved account/session and sends a clearing update to the paired Watch; do not equate that with revoking a ChatGPT session on the server. Open the Watch and allow synchronization to finish. Use ChatGPT's account session controls if server-side revocation is needed.

Do not commit configuration overrides, generated Xcode projects, website data, device containers, auth/session exports, signed archives or provisioning material. `.gitignore` is a guardrail, not a secret scanner. Before release, inspect the staged file list and run a scanner over both the tree and Git history.

Voice messages upload recorded audio to ChatGPT for transcription and submit the text to the selected Dot. Server-side retention follows the account/service settings; removing a local outbox entry does not delete a server message. These transcription and messaging endpoints are undocumented browser interfaces. A failed verification or unsupported response is surfaced to the user; the client does not add browser impersonation, integrity-bypass or attestation-override headers.

The simulator fixture uses synthetic account values and a local test peer. It is enabled only for simulator builds through explicit launch arguments; the separate `--voice-ui-fixture` layout flag is also DEBUG-only and prevents audio, upload and call actions; it does not require a real ChatGPT login or use audio hardware.

This experimental client and its custom WebRTC transport have not undergone an independent security audit. Report vulnerabilities without including account credentials or raw session data in public issues.
