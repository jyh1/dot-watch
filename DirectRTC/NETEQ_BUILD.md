# Native NetEq dependency

`bash Tools/build-neteq.sh` from the repository root prepares the native dependency before project generation, package tests or Xcode builds. It downloads pinned public sources and build tools into ignored `DirectRTC/.native-neteq-cache`, compiles the selected upstream receiver, and generates `DirectRTC/Vendor/NetEqNative/NetEqNative.xcframework`. Generated dependencies/binaries and recordings must not be committed.

Requirements: macOS on Apple Silicon, Xcode with macOS/iOS/watchOS SDKs, Python 3, Git, and network access for the first preparation. CMake 4.4.4 and Ninja 1.13.2 are provisioned into the isolated cache. A warm preparation verifies the fingerprint and returns without recompiling or altering the linked binary. Preparers are serialized with a file lock; framework output is published via an atomic symlink to a fingerprinted cache directory. Run preparation before active Xcode/package builds. Do not use `--force` while a build is using the native dependency.

## Pinned sources

- WebRTC official origin `https://webrtc.googlesource.com/src`, commit `ddd3e1dc172f322356ca91cb764d57c7b81ed282`.
- Xiph Opus 1.6.1, source archive SHA-256 verified by the preparer.
- Abseil 20260107.1, source archive SHA-256 verified by the preparer.

All 125 selected WebRTC source files are genuine upstream files, with real signal processing and codec implementations. No replacement jitter buffer, educational VAD/SPL stubs or simulated decoder is included. The upstream field-trial registry header is generated by its official script. Registration diagnostics are disabled; field-trial values otherwise remain defaults. WebRTC's BSD-style license/patent grant/authors, Opus notices and Abseil Apache-2.0 license are retained in `Native/licenses`.

The local C bridge selects upstream Opus mono decoding at 48 kHz and native NetEq. The production wrapper requests minimum adaptive delay 80 ms and maximum target delay 500 ms. The maximum target is **not** a hard limit on every transient backlog or source-to-output age. That selected configuration was evaluated offline and can add delay during bursts.

## Apple slices

| SDK | Architectures |
| --- | --- |
| macOS | arm64 |
| iOS device | arm64 |
| iOS Simulator | arm64 |
| watchOS device | arm64, arm64_32 |
| watchOS Simulator | arm64 |

Minimum deployment targets are macOS/iOS/watchOS 26, matching this package. Intel Mac/simulator slices are not currently provided. Native Watch source uses the portable Apple/POSIX path (`WEBRTC_IOS` on watchOS); original audio algorithm sources are unmodified. All listed device/simulator slices have compiled. Cross-compilation is not physical Watch audio/performance validation.

The public C module is `CDotNetEq`, exposed by `Native/include/CDotNetEq.h`. Calls are serialized on the Swift codec queue. Timestamps are monotonic microseconds: original arrival is retained as receive metadata, while actual processing/render time advances the receiver clock. Every successful audio pull produces exactly 480 mono PCM16 samples at 48 kHz (10 ms). PCM buffers are supplied by the caller. No audio device, network connection or sign-in is opened by the native library.

The separate raw Opus decoder helper supports offline timestamp-order comparison; it does not play audio or send microphone data. Microphone encoding remains the existing Apple 24 kHz encoder.

## Verification and build provenance

Each completed cache package has `provenance.json` identifying the source pins, SDK versions, architectures and build fingerprint. Compiler path prefixes are remapped in generated binaries. Public sources/recipes contain no personal workspace paths or private captures.

The native C bridge and Swift wrapper reproduce the selected offline receiver output bit-for-bit over three recorded traces, with matching receiver statistics. Package tests cover mono tone/frequency, fixed 10 ms output, RTP wrapping, PLC/loss, reset and invalid input/clock boundaries. Physical listening and Watch runtime resource checks remain separate deployment validations.
